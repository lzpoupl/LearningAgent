# 介绍

本项目拟设计并实现一个集成AI Agent的通用学习助手系统，将大部分学习行为所需的软件功能纳入，以支撑学生的个人终生学习。系统首先面向具有考研需求的大学生，提供数学、外语等独立学习模块。系统是高度可定制化的，可以让用户自行配置，来支持计算机科学等其他学科。

本项目要满足以下需求：
(1) 结构化学习资产管理，比如Anki卡片，英文单词本
(2) 非结构化学习资产管理，比如各种PDF文件
(3) 实现Anki间隔重复复习系统
(4) 用户根据学科特点进行Agent配置，并与AI对话进行学习

利用系统，用户可能完成的学习流程：
用户做数学问题 -> Agent根据用户的学习资产批改并提出新结论 -> 用户将结论记录进Anki 卡片 -> 卡片被用户多次复习，用户成功学会知识点

技术栈：Tauri + Vue3

# 需求

- 用户计算犯错，AI看完他的解题过程，给出基于认知负荷降低的细粒度策略，再从粗粒度上尝试找到优化算法
- 用户不理解某英文句子中的生词，AI讲解给用户，然后将此句子加入Anki复习计划，间隔重复地让用户翻译这个句子
- AI指认前置知识
- Anki制卡、间隔重复复习策略
- Anki卡片中引用学习资料
- 对于每一门科目（比如操作系统）的课件读入知识库，让Agent能够看到
- 今天学了多少小时？统计

# 架构设计

用户与AI的对话以会话为基本单位。每次用户与大模型的对话，都在初始上下文中加入学习资产索引，然后大模型按需调用工具来查看。每个Agent有自己的配置文档，用来告诉大模型这个智能体是做什么的，比如数学Agent和英语Agent要做的事肯定不同，配置也就不同。

Agent可以对资产进行读写，但要经过权限模块，要具体到某个学习资产，对读写权限分别管理。Anki牌组是一种结构化学习资产，除此以外还有例如错题本和英文例句本等，所有结构化学习资产都存储在数据库中。用户自己的笔记、PDF、PPT属于非结构化学习资产，以文件形式存储在文件系统上。

## Anki模块

### 用例

- 获取某牌组的所有卡片，附带查询条件

- 新增牌组/path/to/a
- 增加卡片到牌组/path/to/a

改：

- 移动整个牌组/path/to/a 到/path/to/b
- 变更单张卡片的所属牌组到/path/to/a
- 用户对某卡片作答“重来”、“困难”、“良好”、“简单”
- 彻底忘记某张卡片（恢复到初始记忆状态，好像这张卡是刚新增的一样）
- 修改卡片正面/背面内容

删：

- 删除牌组/path/to/a
- 删除某id的卡片

- 上传图片

### 牌组路径设计

根牌组是一个虚拟的根节点，路径为`/`，所有牌组都在根牌组下，根牌组没有卡片，根牌组不允许被删除或移动。
牌组路径是一个字符串，形如`/path/to/a`，表示牌组a是牌组to的子牌组，牌组to是牌组path的子牌组。牌组路径中每一个路径节点名称都不允许出现空格以及"/"字符。

### 设计

一个Agent的配置包括：

- Agent名称
- Agent描述
- Agent的可用工具id列表

一个Agent可调用的工具由这几部分构成：

- 工具的所属组
- 工具的id
- 工具描述
- 参数（json）
- 返回值（json）

agent对某个工具的权限分为三类：允许、询问、拒绝。允许表示agent可以直接调用该工具，询问表示agent调用工具前需要向用户确认，拒绝表示agent不能调用该工具。

目前实现Agent的工具有：

- Anki卡片访问
- 非结构化资产访问
- 反问用户问题
- 后续扩展....请在代码中创建合适的抽象，使用合适的设计模式

一个非结构化资产bucket对应文件系统上的一个目录，用户可以创建bucket指向特定的目录。解除bucket时仅仅删除数据库中该bucket的记录，不会删除文件系统上的真实文件。
